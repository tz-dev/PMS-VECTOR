# E17 — Fixpoint without Authority

**Paper:** Appendix E.17  
**Format:** Micro-Countercase  
**Adversarial:** No  
**Load-bearing:** No

## Tempting Misclassification

A coordination process cannot reach joint integration, but an operational output must still be produced before a deadline. From the resulting functional necessity, one might jump to:

> person A should rule.

That inference confuses the required function with a particular bearer and with the bearer's authority.

## Minimal Countercase

The scene does support:

\[
FixpointRequirement.
\]

But the same fixpoint function can be carried by at least two different arrangements:

- a rotating designated coordinator;
- a pre-agreed escalation protocol.

PMS-CONFLICT supplies the lineage for a fixpoint requirement where integration fails but continuity or output remains required, while also allowing the function to be carried by a person, role, procedure, or institutional mechanism. PMS-VECTOR makes the boundary explicit.

No ROT (Rotation) is required for this micro-countercase. The discrimination is already produced by the coexistence of the functional requirement and multiple possible carriers.

## Correct VECTOR Result

The bounded result is:

\[
\boxed{
FixpointRequirement
\neq
BearerAuthority.
}
\]

The fixpoint is a **function before it is a bearer**. The need for stabilization is real; the authority of any particular bearer is a separate question requiring separate warrant.

## What Does Not Follow

- `FixpointRequirement` does not imply `BearerAuthority`.
- The need for some fixpoint function does not establish that person A should rule or that one particular bearer is legitimate.

## Repository Boundary

This is a paper-linked discriminative fixture, not a governance recommendation. It does not choose between the rotating coordinator and escalation protocol, endorse asymmetric leadership, or establish the legitimacy of either arrangement. It records only the structural separation between a required stabilization function and bearer authority.
