# E07 — Option Invisibility

**Paper:** Appendix E.7  
**Format:** Micro-Countercase  
**Adversarial:** No  
**Load-bearing:** No

## Tempting Misclassification

Two departments currently represent two paths in their orientation: keep the current process, or replace it entirely. The fixture does **not** treat this A/B representation as an exhaustive claim that no further effective option exists.

When an inside/outside ROT (Rotation) reveals a staged transition C, the tempting interpretation is that the rotation has created a new option.

That interpretation confuses visibility with option existence.

## Minimal Countercase

A shared support unit already possesses authority to separate one blocking dependency. Because that authority already exists in the same organizational scene, staged transition C is genuinely available and actionable before the rotation.

Before ROT, however, C is absent from the departments' current orientation:

\[
Available(C)\land\neg Visible(C).
\]

The inside/outside rotation changes the view by including the support-unit relation. It does not create the authority, the blocking-dependency relation, or the staged path itself. C becomes visible because a pre-existing relation becomes legible.

## Correct VECTOR Result

The apparent new-option interpretation requires revision. The correct classification is **Option Invisibility**, not Option Creation.

Crucially, the fixture does not convert prior nonvisibility into an exclusion claim:

\[
\neg Visible(C)\not\Rightarrow\neg Available(C).
\]

No **Option Blindness** is diagnosed merely because C was previously invisible. Blindness would require an unsupported exclusion of C from the relevant current or transformably reachable option field.

The repository therefore records **Revision Required** only for the apparent creation interpretation: C was a pre-existing actionable path whose visibility changes under ROT.

## What Does Not Follow

- ROT revealing C does not imply that ROT created C.
- Absence of C from the initial orientation does not establish absence of C from the effective option field.
- Option Invisibility does not by itself establish Option Blindness.
- The case does not claim that every newly visible path was previously actionable; that status is warranted here only because the fixture supplies the pre-existing support-unit authority and actionable staged route.

It is a paper-linked discriminative fixture, not empirical validation, and it does not enact an architecture-level change. `cases/E07.yaml` is the machine-readable companion; the paper remains the theoretical authority for the case.
