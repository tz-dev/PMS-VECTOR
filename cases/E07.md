# E07 — Option Invisibility

**Paper:** Appendix E.7  
**Format:** Micro-Countercase  
**Adversarial:** No  
**Load-bearing:** No

## Tempting Misclassification

Two departments are initially assumed to have only two options: keep the current process, or replace it entirely. When an inside/outside ROT (Rotation) reveals a staged transition, the tempting interpretation is that the rotation has created a new option.

That interpretation confuses visibility with option existence.

## Minimal Countercase

A shared support unit already possesses authority to separate one blocking dependency. Because that authority already exists in the same organizational scene, staged transition C is genuinely available and actionable before the rotation.

Before ROT (Rotation), however, C is absent from the departments' current orientation:

\[
Available(C)\land\neg Visible(C).
\]

The inside/outside rotation changes the view by including the support-unit relation. It does not create the authority, the blocking-dependency relation, or the staged path itself. C becomes visible because a pre-existing relation becomes legible.

## Correct VECTOR Result

The A/B-only option-field representation requires revision. The correct classification is **Option Invisibility**, not Option Creation.

The repository therefore records **Revision Required**: the initial option map loses, while the corrected map includes C as a pre-existing actionable path whose visibility changes under ROT.

## What Does Not Follow

ROT revealing C does not imply that ROT created C. Likewise, absence of C from the initial orientation does not establish absence of C from the effective option field.

The case also does not claim that every newly visible path was previously actionable. That status is warranted here only because the fixture itself supplies the pre-existing support-unit authority and the actionable staged route.
