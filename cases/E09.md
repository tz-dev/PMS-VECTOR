# E09 — Special-Case Probe Produces Orientation

**Paper:** Appendix E.9  
**Format:** Micro-Countercase  
**Adversarial:** No  
**Load-bearing:** No

## Tempting Misclassification

A conflict currently has no viable shared procedure. The analyst constructs a special-case frame \(F^*\) in which both parties are assumed to have equal decision authority. Under that altered frame, a shared procedure becomes viable.

The tempting mistake is to transport that result back into the current frame \(F_0\) and treat the shared procedure as a current option.

## Minimal Countercase

The special case changes one material condition: the decision-authority relation. The contrast therefore supports bounded orientation about what carries the blockage in the current frame.

DIR (Direction) here is limited to that frame-bounded orientation: unequal decision authority is identified as the operative asymmetry blocking the shared procedure under \(F_0\).

But the option relation remains:

\[
o(F^*)\not\Rightarrow o(F_0).
\]

The counterfactual does not itself supply authority, practical control, or an effective mechanism that would make the altered condition real in the current field.

## Correct VECTOR Result

The correct result is **Bounded Orientation**. The probe is analytically valid because the declared difference between \(F_0\) and \(F^*\) reveals the blocking authority asymmetry.

It is not a current option-space transformation. No node or relation change in the real option field is recorded.

\[
\boxed{invalid\ as\ option\not\Rightarrow invalid\ as\ probe}
\]

and:

\[
\boxed{orientation\ gain\neq option\text{-}status\ change}.
\]

## What Does Not Follow

- Viability under \(F^*\) does not establish availability, actionability, or viability under \(F_0\).
- A useful special-case probe does not enlarge the current real option set.

## Repository Boundary

E09 is a paper-linked discriminative fixture for the Special-Case Probe boundary. It records a frame contrast that improves orientation while preserving the distinction `valid probe != valid option`. It does not add a new option status, a new ROT (Rotation) family, or a practical transformation claim.
